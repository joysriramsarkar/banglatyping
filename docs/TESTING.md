## ১. টেস্টিং ফিলোসফি ও আর্কিটেকচার

বাংলা একটি মরফোলজিক্যাল এবং জটিল স্ক্রিপ্ট (Complex Text Layout / CTL) সমৃদ্ধ ভাষা। সাধারণ স্পেস-বেসড শব্দ গণনা বা স্ট্রিং-লেন্থ ইংরেজি টাইপিং প্ল্যাটফর্মে কাজ করলেও বাংলা ভাষায় তা সম্পূর্ণ অকার্যকর।

আমাদের টেস্টিং আর্কিটেকচার ৩টি মৌলিক নীতি মেনে চলে:
1. **গ্রাফিম-ফার্স্ট নির্ভুলতা (Grapheme-First Accuracy):** প্রতিটি টাইপিং টেস্টে `Intl.Segmenter` এবং ইউনিকোড এনএফসি (NFC) স্বাভাবিকীকরণ যাচাই করা হয়।
2. **জিরো-রিগ্রেশন অ্যাক্সেসিবিলিটি (Zero-Regression Accessibility):** প্রতিটি UI কম্পোনেন্টে স্ক্রিন রিডার (ARIA) ও কীবোর্ড নেভিগেশনের জন্য স্বয়ংক্রিয় টেস্ট বলবৎ থাকে।
3. **অনলাইন/অফলাইন ডুয়াল রেজিলিয়েন্স (Dual Resilience):** গেস্ট মোড (LocalStorage) এবং ক্লাউড মোড (Supabase PostgreSQL) উভয় পথেই ডাটা ফ্লো টেস্ট করা হয়।

## ৩. টেস্ট চালানোর কমান্ডসমূহ

```bash
# সব ইউনিট ও কম্পোনেন্ট টেস্ট রান করুন
npm test

# নির্দিষ্ট ফাইল টেস্ট করুন (যেমন অ্যাক্সেসিবিলিটি টেস্ট)
npx jest src/__tests__/components-a11y.test.tsx

# কোড কভারেজ রিপোর্টসহ টেস্ট রান করুন
npm run test:coverage

# ওয়াচ মোডে টেস্ট রান করুন (ডেভেলপমেন্টের সময়)
npm test -- --watch

# সিআই (CI) মোডে টেস্ট রান করুন (কঠোর কভারেজ গেটসহ)
npm run test:ci

# টাইপস্ক্রিপ্ট টাইপ চেক
npm run typecheck

# প্লেরাইট E2E টেস্ট রান করুন
npm run test:e2e

# প্লেরাইট ইন্টারঅ্যাক্টিভ UI মোডে টেস্ট রান করুন
npm run test:e2e:ui
```

## ৪. বাংলা ভাষা ও গ্রাফিম টেস্টিং নির্দেশিকা

বাংলা টেক্সট টেস্ট করার সময় নিচের বিষয়গুলো কঠোরভাবে অনুসরণ করতে হবে:

### ক. ইউনিকোড নরম্যালাইজেশন (Unicode Normalization)
অপারেটিং সিস্টেম ও কীবোর্ড ভেদে ইউনিকোড সিকোয়েন্স ভিন্ন হতে পারে (যেমন: `ড়` হতে পারে `\u09DC` অথবা `\u09A1\u09BC`)।
```ts
// সঠিক পদ্ধতি: সর্বদা NFC নরম্যালাইজেশন যাচাই করুন
expect(normalizeBengali(input)).toBe(normalizeBengali(expected));
```

### খ. গ্রাফিম সেগমেন্টেশন টেস্ট (যুক্তাক্ষর ও কার-চিহ্ন)
একটি বাংলা অক্ষরের ভিজ্যুয়াল ইউনিটে একাধিক ইউনিকোড কোডপয়েন্ট থাকে (যেমন `ক্ষ্ম` = ক + ্ + ষ + ্ + ম = ৫টি কোডপয়েন্ট, কিন্তু ১টি গ্রাফিম)।
```ts
test('সঠিক গ্রাফিম সেগমেন্টেশন', () => {
  const graphemes = segmentGraphemes('বিজ্ঞান');
  // [বি, জ্ঞা, ন] = ৩টি গ্রাফিম
  expect(graphemes.length).toBe(3);
  expect(graphemes[0]).toBe('বি');
  expect(graphemes[1]).toBe('জ্ঞা');
  expect(graphemes[2]).toBe('ন');
});
```

### গ. টাইপিং ত্রুটি শ্রেণিবিভাগ (Typing Error Taxonomy)
- `wrong-hasanta`: হসন্ত না দিলে বা অতিরিক্ত দিলে।
- `wrong-kar`: স্বরচিহ্ন কার সংক্রান্ত ভুল।
- `wrong-order`: সঠিক বর্ণ কিন্তু ভুল অনুক্রমে টাইপ করলে (যেমন: র্ক বনাম ক্র)।
- `space-error`: স্পেসজনিত ভুল।

## ৫. অ্যাক্সেসিবিলিটি (a11y) টেস্টিং নীতিমালা

প্রতিটি ইন্টারঅ্যাক্টিভ কম্পোনেন্ট পরীক্ষার জন্য নিচের নিয়মগুলো আবশ্যিক:

1. **ডেকোরেটিভ বনাম কনটেন্ট আইকন:**
   - আইকন ও ব্যাকগ্রাউন্ড শেপে অবশ্যই `aria-hidden="true"` থাকতে হবে।
   - টেস্টে যাচাই করুন:
     ```ts
     expect(container.querySelector('[aria-hidden="true"]')).toBeInTheDocument();
     ```
2. **স্ক্রিন রিডার প্রগ্রেস লাইভ রিজিয়ন:**
   - ভিজ্যুয়াল হাইলাইটেড টেক্সট স্ক্রিন রিডারের জন্য বারবার পড়া অনুপযোগী। তাই ভিজ্যুয়াল টেক্সটকে `aria-hidden="true"` রেখে পৃথক `sr-only` এলিমেন্টে `aria-live="polite"` দিয়ে প্রগ্রেস ঘোষণা করতে হবে।
3. **কীবোর্ড কন্টেইনার রোল:**
   - ভার্চুয়াল কীবোর্ড গ্রিডে `role="img"` এবং বিস্তারিত তথ্যবাহী `aria-label` থাকতে হবে।

## ৬. মক ও ফেক অবজেক্ট হ্যান্ডলিং

### ক. Lucide Icons ESM Mock
Next.js এবং Jest-এর CommonJS ট্রান্সপাইলেশনের জন্য Lucide আইকনগুলোকে প্রক্সি মক করা হয়:
```ts
jest.mock('lucide-react', () => {
  return new Proxy({}, {
    get: (_target, prop) => (props: any) => <span data-testid={`lucide-${String(prop)}`} {...props} />,
  });
});
```

### খ. Web Audio API Mock
ব্রাউজারের বাইরে অডিও কোড টেস্ট করার জন্য সিন্থেসাইজার নোডগুলো মক করা হয় (`createOscillator`, `createGain`, `createBiquadFilter`, `createBuffer`)।

## ৭. কভারেজ পলিসি ও সিআই গেইট

`jest.config.js`-এ প্রজেক্টের গ্লোবাল লাইন কভারেজ থ্রেশহোল্ড নির্ধারণ করা আছে:
```js
coverageThreshold: {
  global: { lines: 80 },
}
```
- কোনো নতুন পিআর (PR) বা মডিউলে টেস্ট ছাড়া কোড পুশ করা যাবে না।
- টাইপিং ইঞ্জিন (`src/lib/typing/`) ও কারিকুলাম ইঞ্জিনের কভারেজ ৮৫%+ বজায় রাখা বাধ্যতামূলক।
